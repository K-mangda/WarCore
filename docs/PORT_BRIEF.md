# Port brief - for the model/session that does the full port

Goal: make the web game (Vite + TypeScript + React + three.js, this repo) match the real Megabonk as closely as possible, using the extracted data. The owner authorised extraction from their own install. Commit and push regularly; keep docs updated.

## Inputs (all under `.local-evidence/`, git-ignored; produce with `node tools/extract_all.mjs`, see [EXTRACT_ALL.md](EXTRACT_ALL.md))
- `unity-dump/<file>/objects.jsonl`: every Unity object with full typetree; `textures/ sprites/ audio/ meshes/`.
- `decompile6/*.c`: Ghidra pseudocode per function, file name `<tier>__<Class>.<method>_<rva>.c`. Class/field names and offsets: `C:\Users\Korawit\Desktop\megabonk_decompiled\dump.cs` (Il2CppDumper). Image base 0x180000000.
- Already distilled: `docs/rea/*.json`, `src/data/NativeData.ts` (generated by `tools/build_web_data.py`).

## Method that worked
1. Read data from assets (UnityPy) for numbers/tables; decompile only for behaviour. IL2CPP typetrees need the fixed generator in `tools/dump_all_unity.py` (moves the `references` node last).
2. Mark every fact with an evidence tier in docs: V verified (decoded/disassembled), I inferred, P provisional (web choice), U unknown. Never present I/P as V.
3. Keep `docs/NEXT_STEPS.md` current, especially its "Parking lot".
4. New TypeScript modules must be added to the transpile list of each `tools/check_*.mjs` that loads them, or CI fails with ERR_MODULE_NOT_FOUND.
5. Verify UI in the browser (levelup.html / Lab) against the user's screenshots; the user play-tests by hand.

## Known pitfalls
- `docs/TEMPORARY_IMPLEMENTATIONS.md` is mixed encoding/line endings: edit with exact replacements only.
- Source files use CRLF; normalise before string replaces.
- Ghidra imports take ~35 min per run; batch everything in one run; per-call timeout must be passed as `callTool(params,{timeout})`.
- `check_deploy.mjs` needs `MSYS_NO_PATHCONV=1` and a `--base=/WarCore/` build.
